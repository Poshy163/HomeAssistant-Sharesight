# Sharesight integration audit, September 2026

## Outcome and scope

Release **2.3.1** completes the unfinished portfolio-metric and history work,
corrects confirmed data/reliability errors, and keeps the published
`SharesightAPI==1.5.0` dependency. No production files, configuration entries,
registries, tokens, or portfolio records were changed during this audit.

At the start, all 28 local integration files already matched the deployed
2.3.0 files, although 21 repository files were uncommitted. That work was
preserved, reviewed and completed. The metric additions below were therefore
already present in the starting live installation; they are not presented as
new live features delivered by this audit.

## Confirmed findings and fixes

| Finding | Root cause and final behavior | Implementation / coverage |
|---|---|---|
| Small valid positions discarded | A dust tolerance applied to every quantity. Nonzero fractional/short positions now survive unless explicitly invalid dust; actual zero positions still close. | `analytics.is_open_position`; `test_audit_regressions.py` |
| Missing holding values became 0% weight | The shared value helper defaulted to zero. Weight calculation now uses an unknown default. | `sensor._get_holding_value`; allocation regressions |
| Partial closed-position returns appeared complete | Missing gains were omitted from a sum. Any missing closed-position gain now makes the aggregate unknown. Empty closed-position lists still total zero. | `sensor._raw_native_value`; missing/null/nonfinite tests |
| Payout total could mix currencies or accounting scopes | Missing exchange rates fell back to native amounts, and empty/failed feeds could fall back to the combined open-holdings report. Normalization now converts known currencies safely, returns unknown for incomplete totals, and returns zero for an explicitly empty successful feed. | `coordinator._post_process`, `sensor._get_income_summary`; six payload regressions |
| All-time report could become YTD | Unknown inception used a January fallback. Invalid dates are removed and the request omits `start_date`, using the documented API `portfolio` default. | `_normalise_portfolio_detail`, `_slow_endpoints`; invalid date/type tests |
| Report reuse had different limited-holding controls | All-time used `include_limited=true`, extended periods did not. Every V3 performance request now uses that control; V2 fallback removes V3-only parameters. Inception-clamped periods can reuse the equivalent all-time report. | `_performance_params`; request-scope regression |
| “Monthly” label implied the wrong period | Existing calculation is 30 elapsed days, not calendar month. Display text now says “30-Day”; translation keys, unique IDs and calculation remain unchanged. | `enum.py`, `strings.json`, English translations |
| Impossible financial-year settings were accepted | Values such as April 31 were clamped into another valid setting. Impossible month/day combinations now use the documented default; February 29 remains supported. | `dates.py`; leap/month/FY/DST tests |
| Reauthentication reload API modernization | The HA reload helper is deprecated alongside update listeners. Credentials are updated through `async_update_and_abort`, followed by one explicit reload; token-only updates are ignored by the options listener. Both loaded and not-loaded cases are tested. The configured portfolio must remain visible to the new authorization. | `config_flow.py`; HA config-flow regressions |
| Runtime diagnostic keys leaked IDs | Cooldown/cache keys can embed a portfolio identifier. These keys are now redacted alongside values. Existing shape-only diagnostics and token redaction remain. | `diagnostics.py`; HA privacy tests |
| Historical risk metrics were not reconstructible | Inception history may be thinned; recent data lacks each prior day's complete 45-day window. Removed historical high-water/drawdown/volatility reconstruction. Only actual portfolio-value points and 7/30-day changes with a real baseline are imported. | `statistics_import.py`; sparse-source, window, metadata, idempotency and cancellation tests |

The daily and weekly date ranges in the supplied capture are correctly equal:
the capture was on a Monday and the integration uses Monday-to-date. Annualised
returns remain Sharesight's reported values with report flags/context. Calendar
YTD and portfolio financial-year reporting remain distinct. The portfolio
timezone governs reporting and date-only history conversion, including fractional
UTC offsets. No live OAuth session was copied into a second client.

## Capability coverage and cost

See [API capability audit](audit-api-capabilities.md), the complete
[endpoint inventory](endpoint-usage.md), and [entity matrix](entity-matrix.md).

| Status | Capability and outcome |
|---|---|
| Already implemented | OAuth, multiple portfolio coordinators, current/period performance, holding metrics, allocations, payouts/trades/cash summaries, dividend calendar, benchmark/watchlist, AU CGT, diagnostic entities, activity events, on-demand read services. These were traced rather than recreated. |
| Fetched but underused | Unfinished additions expose market/holding weights, holding names/markets, portfolio sale-allocation/CGT settings, all-time gain components and closed-position summaries. Embedded classifications remain available when optional instrument metadata is absent. These need no new endpoint. |
| Supported but not implemented | Per-instrument price and per-holding value histories remain client capabilities without per-item HA polling; performance-index history remains an on-demand expansion candidate. Avoids multiplying requests by holdings. |
| Unavailable for this account | No new authenticated entitlement probes were made. The capture's unavailable list was empty. Empty upcoming payouts and missing label rows are empty data, not proof of an account restriction. |
| Unverified | Current entitlement to routes tagged internal/mobile beyond the captured/live cached data; unsupported news/market/FX routes remain excluded from polling. No speculative replacement paths or forecasts added. |

Relative to the committed pre-2.3 work, the completed metric additions add
**7 portfolio sensors + 1 per market + 3 per holding**. Relative to the starting
live 2.3.0 files there are no additional sensor families. Existing options gate
holding families, extended reports, backfill and automatic stale-device removal;
existing registry customizations are preserved.

There are no added periodic endpoints. The base frequent tier issues four
requests per poll, while slow/optional sources retain their own cadence and
bounded carry-forward. Extended periods clamped to inception reuse all-time
data. Account/application request gates retain the 360/minute and three-heavy-
report limits, timeouts and backoff. Separate source caches and independent
activity baselines prevent one optional failure from invalidating unrelated data.
The client uses bounded cursor pagination; it has no response cache.

Backfill retains its existing optional inception-history request. Trend imports
reuse the recent source already fetched, add no HTTP requests and create no new
entities. It can fill at most the preceding 30 days, and only where the actual
7/30-day comparison baseline exists. It never invents market-holiday samples,
overwrites existing hourly samples or relabels incompatible currency metadata.
Cancellation stops the derived import when an entry unloads.

## Read-only production baseline

SMB share discovery located the Home Assistant `config` share. Its `.HA_VERSION`
and MCP agreed on **Home Assistant 2026.9.1**, Python **3.14.6**, HA OS. The
Sharesight entry was loaded, not degraded, and had no parked/unsupported endpoints
or logged failures in its diagnostics. The recent sampled log window showed
successful polls; this is not a claim that the entire historical log is error-free.

Diagnostics reported 890 registry entities. A name-search snapshot returned
891 matching states (including integration-adjacent states): 838 had values,
50 were unknown and 3 unavailable. Registry inspection traced two unavailable
states to a previously saved label absent from current label allocation, and the
third to the retired instrument-news family. They were not removed or rebound.

Routine attributes for those 891 states totalled **122,040 JSON characters**;
the largest was **1,943**, with none over 16,384. These are serialized character
counts, not database byte measurements or a measured daily Recorder growth rate.
Raw history stays in coordinator/service data rather than routine state attributes;
large compatible attributes are excluded from Recorder. The personal export
remains outside Git. Previously inherited real portfolio IDs in test fixtures
were replaced with synthetic identifiers.

## Deployment and rollback (approval required)

No deployment has occurred in this audit. The prepared local package and diff
compare final integration files against the unchanged live 2.3.0 source baseline.
The only runtime requirement remains the already published
`SharesightAPI==1.5.0`; no local client package must be released first.

After explicit deployment approval:

1. Create a Home Assistant backup including configuration and Recorder data;
   separately copy `custom_components/sharesight` to a dated backup outside that
   directory. Keep credentials and `.storage` out of Git and the source package.
2. Recheck installed HA/Python and dependency versions, confirm the baseline hash
   list still matches, then copy the reviewed 2.3.1 integration directory, excluding
   bytecode. Compare all deployed source SHA-256 hashes with the package manifest.
3. Validate configuration, then restart HA once. Do not edit `.storage` or registry
   files to force a migration. Existing config-entry/unique-ID migration logic
   handles old entries through supported HA APIs.
4. Verify the Sharesight entry loads, representative values/currencies and IDs,
   both report periods, optional-source availability, diagnostics, Recorder repairs
   and logs. Wait through a complete frequent poll and a slow refresh. A restart
   alone is not acceptance evidence.
5. If validation fails, restore the backed-up integration directory and restart.
   The dependency is unchanged. If the approved rollout imported unwanted history,
   restore the supported full backup containing Recorder data; reverting source
   alone does not erase statistics. Do not delete statistics/registries ad hoc.

Existing “Monthly” entities retain registry IDs and user overrides, with clearer
default display text. Existing historical rows are preserved; corrected missing
data may now be unknown where older code published misleading zero/partial totals.
Previously imported inaccurate risk history cannot be distinguished safely from
native history by this release, so it is not automatically erased.
